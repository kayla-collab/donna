1. Introduction & Purpose

Donna Roggio LLC ("Company," "we," "us," or "our") is committed to protecting the security, confidentiality, and integrity of all data processed through the Personal Money Mastery System ("the System," "the Application," or "the Service").

This Security Policy outlines the technical, administrative, and physical safeguards we implement to protect user data, including sensitive financial information accessed through third-party bank connection services.

Our Security Commitment:
We treat your financial data with the same level of care and protection that we would want for our own. Security is not an afterthought—it is foundational to everything we build.

1.1 Document Purpose

This document serves to:

  • Define our security standards and practices
  • Communicate our data protection measures to users
  • Satisfy compliance requirements for financial data handling
  • Establish guidelines for incident response and breach notification
  • Meet requirements for third-party integrations (e.g., Plaid)

2. Scope of This Policy

2.1 What This Policy Covers

This Security Policy applies to:

  • The Personal Money Mastery System Google Sheets application
  • All associated Google Apps Script code and HTML interfaces
  • Data stored in users' Google Sheets documents
  • Data stored in Google Apps Script Properties
  • Third-party integrations (Plaid, bank connections)
  • All users, administrators, and personnel with access to the System

2.2 What This Policy Does Not Cover

  • Security of users' Google accounts (governed by Google's policies)
  • Security of users' bank accounts (governed by respective financial institutions)
  • Third-party services' internal security (governed by their own policies)

3. Data Collection & Types

3.1 Categories of Data Collected

Data Category Examples Sensitivity Level Storage Location
User Identity Email address, name Medium Google Account / Script Properties
Financial Transactions Date, merchant, amount, category High User's Google Sheets
Account Information Account name, type, last 4 digits High Script Properties (encrypted)
Account Balances Current balance, available balance High User's Google Sheets
Access Tokens Plaid access tokens Critical Script Properties (encrypted)
User Preferences Category mappings, settings Low Script Properties

3.2 Data We Do NOT Collect

We Never Collect or Store:
  • Full bank account numbers
  • Routing numbers
  • Bank login credentials (usernames/passwords)
  • Social Security numbers
  • Credit card CVV codes
  • Driver's license or government ID numbers

4. Data Storage & Protection

4.1 Primary Storage Infrastructure

All data is stored within Google's infrastructure, which provides:

  • SOC 1, SOC 2, and SOC 3 certification
  • ISO 27001 certification
  • FISMA compliance
  • FedRAMP authorization

4.2 Storage Locations

Data Type Storage Method Encryption
Transaction Data Google Sheets cells Google's encryption at rest (AES-256)
Access Tokens Script Properties Google's encryption at rest (AES-256)
User Settings Script Properties / Document Properties Google's encryption at rest (AES-256)
Temporary Cache Cache Service Google's encryption, auto-expires

4.3 Data Isolation

Each user's data is completely isolated:

  • Each user has their own Google Sheets file in their own Google Drive
  • Script Properties are bound to the individual document
  • No shared database or central data repository
  • Users cannot access other users' data under any circumstances

5. Access Control

5.1 User Authentication

Access to the System requires:

  1. Google Account Authentication: Users must be signed into a valid Google account
  2. Document Access: Users must have edit access to their specific spreadsheet
  3. Script Authorization: Users must authorize the Google Apps Script to run
  4. Application PIN (Optional): Secondary PIN protection for sensitive operations

5.2 Authorization Levels

Role Access Level Capabilities
Primary User Full Access All features, bank connections, settings
Guest User Limited Access View and categorize transactions only
Master Admin Support Access Technical support (only with user permission)

5.3 Session Management

  • Sessions are managed by Google's authentication system
  • No persistent sessions stored by the Application
  • Automatic logout follows Google's session timeout policies

6. Third-Party Services

6.1 Services We Use

Service Purpose Data Shared Security Certification
Google Workspace Application platform All application data SOC 2, ISO 27001, HIPAA
Plaid Bank connections Access tokens only SOC 2 Type II, ISO 27001

6.2 Plaid Security

Plaid provides institutional-grade security including:

  • Bank-level 256-bit encryption
  • SOC 2 Type II certification
  • Regular third-party security audits
  • No storage of bank credentials (handled by banks directly)
  • Tokenized access (credentials never touch our system)

6.3 Data Sharing Policy

We Never:
  • Sell user data to any third party
  • Share data with advertisers
  • Provide data to data brokers
  • Use data for any purpose other than providing the Service

7. Bank Connection Security

7.1 How Bank Connections Work

  1. User Initiates: User clicks "Link Bank Account" in the Application
  2. Plaid Link Opens: Secure Plaid interface loads (not our code)
  3. User Authenticates: User enters bank credentials directly with Plaid
  4. Token Generated: Plaid creates a secure access token
  5. Token Stored: We store only the token (never credentials)
  6. Data Retrieved: Token used to fetch transactions via Plaid API

7.2 What We Never See

Bank credentials (username/password) are NEVER:
  • Entered into our application
  • Transmitted to our servers
  • Stored anywhere in our system
  • Visible to our code or personnel

All authentication happens directly between the user and Plaid's secure infrastructure.

7.3 Token Security

  • Access tokens are stored in Google Apps Script Properties
  • Tokens are encrypted at rest by Google
  • Tokens cannot be used without our Plaid client credentials
  • Tokens can be revoked by users at any time
  • Tokens do not grant ability to move money or make payments

8. Encryption Standards

8.1 Data in Transit

Connection Encryption Protocol
User ↔ Google Sheets TLS 1.3 HTTPS
Google Apps Script ↔ Plaid TLS 1.2+ HTTPS
Plaid ↔ Banks TLS 1.2+ / mTLS HTTPS

8.2 Data at Rest

  • Google Infrastructure: AES-256 encryption
  • Automatic Key Management: Google manages encryption keys
  • No Unencrypted Storage: All data encrypted by default

9. Incident Response

9.1 Incident Classification

Severity Description Response Time Example
Critical Active data breach or compromise Immediate (< 1 hour) Unauthorized access to tokens
High Potential security vulnerability < 24 hours Reported security bug
Medium Security concern, no active threat < 72 hours Suspicious activity report
Low Security improvement opportunity < 1 week Security enhancement request

9.2 Incident Response Procedure

  1. Detection: Identify and confirm the incident
  2. Containment: Isolate affected systems/accounts
  3. Assessment: Determine scope and impact
  4. Notification: Notify affected users within 72 hours
  5. Remediation: Fix the vulnerability
  6. Recovery: Restore normal operations
  7. Post-Incident Review: Document lessons learned

9.3 Breach Notification

In the event of a data breach affecting user financial data, we will:

  • Notify affected users via email within 72 hours
  • Provide details of what data was affected
  • Explain steps being taken to address the breach
  • Offer guidance on protective measures users can take
  • Report to relevant regulatory authorities as required

10. User Responsibilities

10.1 Account Security

Users are responsible for:

  • Maintaining the security of their Google account
  • Using strong, unique passwords
  • Enabling two-factor authentication (strongly recommended)
  • Not sharing their spreadsheet with unauthorized individuals
  • Logging out of shared or public computers

10.2 Reporting Security Concerns

Users should immediately report:

  • Unauthorized access to their account
  • Suspicious transactions or activity
  • Potential security vulnerabilities
  • Phishing attempts related to our Service
Report Security Issues To:
Email: security@risingandthriving.com
Response Time: Within 24 hours for all security reports

11. Data Retention & Deletion

11.1 Retention Periods

Data Type Retention Period Deletion Method
Transaction Data User-controlled (indefinite) User deletes from spreadsheet
Access Tokens Until user disconnects bank Automatic upon disconnection
Account Mappings Until user removes User-initiated deletion
Usage Logs 30 days Automatic purge

11.2 User Data Deletion Rights

Users can delete their data at any time by:

  1. Disconnect Bank Accounts: Removes all access tokens
  2. Clear Transaction Data: Delete rows from spreadsheet
  3. Delete Entire File: Remove the spreadsheet from Google Drive
  4. Request Full Deletion: Contact us to ensure complete removal

11.3 Data Portability

Users can export their data at any time:

  • Download spreadsheet as Excel (.xlsx)
  • Download as CSV
  • Download as PDF
  • Copy to another Google Sheets file
